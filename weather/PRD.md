# 랜드마크 날씨 사이트 PRD (제품 요구사항 문서)

> **PRD가 뭔가요?** PRD는 "Product Requirements Document"의 줄임말로, "우리가 무엇을 왜 만들 것인지, 어떻게 동작해야 하는지"를 개발 시작 전에 글로 정리해두는 설계 문서예요. 개발을 시작하면 결정할 게 많아지는데, 미리 정리해두면 중간에 방향을 잃지 않고 빠르게 만들 수 있어요.

## 1. 프로젝트 개요

### 1.1 한 줄 요약
세계 각국의 랜드마크(예: 에펠탑, 자유의 여신상, 도쿄타워 등)를 지도나 목록에서 클릭하면, 그 위치의 실시간 날씨와 현지 시각이 표시되고, 날씨·시간에 어울리게 화면 배경이 자연스럽게 바뀌는 웹사이트를 만든다.

### 1.2 왜 만드나요? (배경)
- 날씨 정보를 숫자와 표로만 보여주는 사이트는 많지만, "여행 감성"을 함께 느낄 수 있는 사이트는 드물다.
- 랜드마크라는 친숙한 요소를 클릭 인터페이스로 사용하면 사용자가 재미있게 여러 나라의 날씨를 탐색할 수 있다.
- Open-Meteo라는 **무료** 날씨 API를 활용하면 별도의 회원가입이나 API 키(API를 쓸 수 있는 비밀번호 같은 값) 없이도 날씨 데이터를 가져올 수 있어, 개인 프로젝트로 부담 없이 시작할 수 있다.

### 1.3 목표 사용자
- 여행을 좋아하거나 세계 각국 날씨에 관심이 있는 일반 사용자
- 포트폴리오/토이 프로젝트로 이 사이트를 보여줄 개발자 본인(이지은님)

## 2. 핵심 기능 (What it does)

| 번호 | 기능 | 설명 |
|---|---|---|
| F1 | 랜드마크 선택 UI | 세계지도 위 마커 또는 랜드마크 카드 목록에서 랜드마크를 클릭할 수 있다 |
| F2 | 실시간 날씨 표시 | 선택한 랜드마크 위치의 현재 기온, 날씨 상태(맑음/흐림/비/눈 등), 체감 정보를 보여준다 |
| F3 | 현지 시각 표시 | 선택한 랜드마크가 있는 지역의 현재 시각을 실시간으로 보여준다 (초 단위로 계속 흐름) |
| F4 | 배경 자동 전환 | 날씨 상태 + 낮/밤 여부에 따라 배경 이미지·색상·애니메이션이 자연스럽게 바뀐다 |
| F5 | 랜드마크 정보 카드 | 랜드마크 이름, 국가, 간단한 설명을 함께 보여준다 (선택 사항) |

### 기능 우선순위 (MVP 기준)
- **필수(MVP)**: F1, F2, F3, F4
- **있으면 좋음(다음 단계)**: F5, 즐겨찾기, 검색 기능, 다국어 지원

> **MVP가 뭔가요?** "Minimum Viable Product"의 줄임말로, "가장 핵심적인 기능만 담아서 먼저 완성하는 최소 버전"을 뜻해요. 처음부터 모든 기능을 넣으려고 하면 완성이 늦어지니, 일단 핵심만 빠르게 만들고 나중에 살을 붙이는 방식이에요.

## 3. 사용자 시나리오 (User Flow)

1. 사용자가 사이트에 접속하면 세계지도(또는 랜드마크 카드 목록)와 기본으로 선택된 랜드마크(예: 에펠탑)의 날씨·시간이 보인다.
2. 사용자가 다른 랜드마크(예: 도쿄타워)를 클릭한다.
3. 화면 중앙 또는 하단 카드에 도쿄의 현재 기온, 날씨 아이콘, 현재 시각이 나타난다.
4. 화면 배경이 "도쿄가 지금 밤이고 비가 오는 중"이라면 어두운 톤 + 비 내리는 애니메이션으로 부드럽게 전환된다.
5. 사용자는 계속 다른 랜드마크를 눌러가며 세계 각국의 날씨를 구경한다.

```
│                                           │

│   │   선택된 랜드마크 이름 · 국가    │     │
│   │   🌡 기온      🕒 현재 시각      │     │
│   │   ☁️ 날씨 상태 텍스트/아이콘     │     │
│   └───────────────────────────────┘     │
│                                           │
│   (배경 전체가 날씨/시간에 따라 변화)       │
└─────────────────────────────────────────┘
```

- 랜드마크 선택 UI는 두 가지 방식 중 선택 가능
  - **A안**: 실제 세계지도(예: Leaflet.js 같은 지도 라이브러리) 위에 마커로 표시 → 시각적으로 화려하지만 구현 난이도가 조금 더 높음
  - **B안**: 나라 이름/랜드마크 이름이 적힌 카드(버튼) 목록을 나열 → 구현이 훨씬 쉽고 빠르게 완성 가능
  - **추천**: 처음에는 **B안(카드 목록)** 으로 MVP를 완성한 뒤, 여유가 있으면 A안(지도)으로 업그레이드하는 것을 추천한다. 이렇게 하면 핵심 기능(날씨 연동, 배경 전환)을 먼저 검증하고, 나중에 지도라는 "겉모습"을 입힐 수 있다.

## 5. 데이터 소스: Open-Meteo API

> **API가 뭔가요?** API(Application Programming Interface)는 "다른 회사나 기관이 가진 데이터를, 정해진 규칙에 따라 우리 프로그램이 요청해서 받아올 수 있는 창구"예요. Open-Meteo는 전세계 날씨 데이터를 이런 창구로 무료 공개해두었고, 우리는 정해진 형식의 웹 주소(URL)에 위치 정보를 담아 요청만 보내면 날씨 데이터를 JSON(텍스트로 된 데이터 형식) 형태로 돌려받을 수 있어요.

### 5.1 기본 특징
- **API 키(비밀 인증키) 불필요**: 회원가입이나 발급 절차 없이 바로 사용 가능 (비상업적 용도 기준)
- **무료 사용량**: 하루 최대 약 10,000건 요청까지 무료 (개인 프로젝트 규모에서는 충분)
- **요청 방식**: 위도(latitude)·경도(longitude) 좌표만 있으면 해당 지점의 날씨를 받아올 수 있음

### 5.2 사용할 엔드포인트 예시
> **엔드포인트가 뭔가요?** API 안에서도 "날씨용 창구", "시간대용 창구"처럼 목적별로 나뉜 세부 주소를 엔드포인트라고 불러요.

```
https://api.open-meteo.com/v1/forecast
  ?latitude=48.8584          (에펠탑의 위도)
  &longitude=2.2945          (에펠탑의 경도)
  &current_weather=true      (현재 날씨 요청)
  &timezone=auto             (해당 위치의 현지 시간대로 자동 변환)
```

- `current_weather=true` → 기온, 풍속, 날씨 코드(weathercode), 낮/밤 여부(is_day) 등을 바로 받을 수 있음
- `timezone=auto` → 좌표만 넣으면 Open-Meteo가 알아서 그 지역의 현지 시간대를 계산해줌 (직접 시간대 계산할 필요 없음)

### 5.3 날씨 코드(weathercode) 해석
Open-Meteo는 세계기상기구(WMO)의 표준 코드를 사용한다. 배경 전환 로직에서 이 코드를 그룹으로 묶어서 사용할 예정이다.

| 코드 범위 | 의미 | 배경 테마(예시) |
|---|---|---|
| 0 | 맑음 | 맑은 하늘 (낮: 파란 하늘, 밤: 별) |
| 1~3 | 구름 조금~많음 | 구름 낀 하늘 |
| 45, 48 | 안개 | 뿌연 회색 톤 |
| 51~67 | 이슬비/비 | 빗방울 애니메이션, 어두운 톤 |
| 71~77 | 눈 | 눈 내리는 애니메이션, 흰색 톤 |
| 80~82 | 소나기 | 강한 비 애니메이션 |
| 95~99 | 뇌우(천둥번개) | 번쩍이는 효과, 어두운 보라/검정 톤 |

### 5.4 현지 시각 계산
- `timezone=auto`로 받아온 시간대 정보(예: `Asia/Tokyo`)를 이용해, 브라우저에서 실시간 시계를 표시한다.
- 처음 API를 호출할 때의 시각을 기준으로 잡고, 이후에는 자바스크립트에서 1초마다 더해주는 방식으로 구현하면 API를 계속 호출하지 않아도 된다. (→ 불필요한 API 요청을 줄여서 무료 사용량을 아낄 수 있음)

## 6. 배경 전환 로직 (핵심 아이디어)

배경은 아래 두 가지 조건의 조합으로 결정된다.

1. **날씨 그룹** (맑음 / 구름 / 안개 / 비 / 눈 / 뇌우) — 위 5.3 표 기준
2. **낮/밤 여부** — Open-Meteo의 `is_day` 값(1=낮, 0=밤)을 그대로 활용

이 둘을 조합하면 최대 6(날씨) × 2(낮/밤) = 12가지 배경 테마가 나온다. 처음에는 배경색 그라데이션 + 간단한 CSS 애니메이션(비/눈 내리는 효과 등) 조합만으로도 충분히 분위기를 낼 수 있고, 실사 이미지를 쓰고 싶다면 나중에 테마별 이미지를 12장 정도 준비해 교체하는 방식으로 확장할 수 있다.

> **왜 이 방식을 추천하나요?** 이미지를 미리 다 만들어두지 않고 "CSS로 색상과 애니메이션을 조합"하는 방식으로 시작하면, 이미지 파일 용량 걱정 없이 빠르게 완성할 수 있고, 나중에 예쁜 이미지로 바꾸고 싶을 때도 테마 이름(예: `sunny-day`, `rain-night`)만 그대로 유지하면 되기 때문에 구조를 바꿀 필요가 없어요.

## 7. 기술 스택 제안

| 영역 | 추천 | 이유 |
|---|---|---|
| 화면(프론트엔드) | HTML + CSS + JavaScript (또는 React) | 초보자는 순수 HTML/CSS/JS로 시작하는 것을 추천. 별도 설치나 빌드 과정 없이 바로 브라우저에서 결과를 확인할 수 있어 학습 곡선이 낮음 |
| 지도(A안 선택 시) | Leaflet.js | 무료 오픈소스 지도 라이브러리로, 마커 클릭 이벤트를 붙이기 쉬움 |
| 날씨 데이터 | Open-Meteo API | 키 없이 바로 호출 가능, 무료 |
| 배포 | GitHub Pages / Vercel / Netlify | 정적 사이트를 무료로 인터넷에 올릴 수 있는 서비스 |

> **프론트엔드가 뭔가요?** 사용자가 브라우저 화면으로 직접 보고 클릭하는 부분(버튼, 지도, 글자, 배경 등)을 만드는 영역을 프론트엔드라고 해요. 이 프로젝트는 별도의 서버(백엔드)를 만들 필요 없이, 브라우저에서 바로 Open-Meteo API를 호출하는 구조로 충분히 완성할 수 있어요.

## 9. 비기능 요구사항

- **반응형 디자인**: 모바일/태블릿/PC 화면 크기에 맞게 레이아웃이 자연스럽게 바뀌어야 한다.
- **로딩 상태 표시**: API 응답을 기다리는 동안 "불러오는 중..." 같은 표시를 보여줘 사용자가 멈춘 줄 오해하지 않게 한다.
- **에러 처리**: 네트워크 오류나 API 응답 실패 시 "잠시 후 다시 시도해주세요" 같은 안내 문구를 보여준다.
- **API 호출 최소화**: 같은 랜드마크를 반복 클릭할 때 매번 새로 요청하지 않도록, 짧은 시간(예: 1~5분) 동안은 이전에 받아온 데이터를 재사용한다(이런 방식을 "캐싱"이라고 부른다).

## 10. 개발 단계 제안 (로드맵)

| 단계 | 범위 | 내용 |
|---|---|---|
| Phase 1 (MVP) | F1(카드 목록)+F2+F3+F4 | 랜드마크 카드 클릭 → 날씨/시간 표시 → 배경 전환까지 동작하는 기본 버전 완성 |
| Phase 2 | 지도 UI 전환, F5 | 카드 목록을 실제 지도(Leaflet.js)로 교체, 랜드마크 설명 카드 추가 |
| Phase 3 | 부가 기능 | 검색 기능, 즐겨찾기, 다국어 지원, 실사 배경 이미지 적용 |

## 11. 성공 지표 (참고용)

- 랜드마크 클릭 후 날씨/배경이 반영되기까지 걸리는 시간(체감상 1초 이내 목표)
- 모바일에서도 레이아웃이 깨지지 않고 잘 보이는지
- 실제로 여러 랜드마크를 눌러봤을 때 배경 전환이 어색하지 않고 자연스러운지
