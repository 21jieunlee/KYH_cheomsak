# PRD — 첨삭진 관리 페이지

## 1. 프로젝트 개요

- **이름**: 첨삭진 관리 (가칭)
- **한 줄 설명**: 논술 학원의 수업 일정·참여 현황과, 첨삭진별 답안지 소지 현황을 한곳에서 관리하는 내부용 웹 서비스
- **유형**: 학원 내부 업무 관리 웹 서비스
- **난이도**: 중급 (역할 구분, 승인 절차가 있어 첫 실습 프로젝트보다 한 단계 복잡함)

## 2. 사용자 시나리오

- **누가 쓰나요?**: 두 종류의 역할
  - **첨삭진**: 여러 학원을 돌며 수업에 참여, 답안지를 배분받아 첨삭
  - **관리쌤**: 전체 일정을 짜고, 인원 배정·변경 요청을 최종 승인/반영
- **언제 쓰나요?**:
  - 수업 참여 여부를 요청/확인할 때
  - 답안지를 배분받았을 때, 또는 누가 가지고 있는지 찾아야 할 때
  - 학생이 보강으로 다른 학원 반으로 이동했을 때
- **왜 쓰나요?**:
  - 지금은 이 모든 일이 카카오톡 3개 방(전체공지방/출석부방/첨삭방)과 관리쌤 한 명의 수작업에 의존하고 있어, 관리쌤의 업무 부담이 크고 답안지 소지자를 찾는 데 시간이 많이 걸림
  - 이를 시스템으로 옮겨 관리쌤의 반복 업무를 줄이고, 정보를 검색 가능한 형태로 남기기 위해

## 3. 핵심 기능 목록

### 필수 기능

**A. 일정표 & 참여 여부 관리**
- 관리쌤이 기본 일정표(날짜/학원/시간/반/필요 인원)를 등록·수정
- 양방향 요청 구조
  - 인원 부족 시: 관리쌤 → 첨삭진 전체에게 "참석 가능하신 분?" 요청
  - 개인 사정 시: 첨삭진 → 관리쌤에게 "이 수업 빠짐/대타 필요" 요청
- 모든 요청은 관리쌤의 최종 승인을 거쳐야 일정표에 반영됨
- 관리쌤용 "승인 대기 목록" 화면 (처리해야 할 요청만 모아 보기)

**B. 답안 소지 현황**
- 첨삭진이 답안지를 배분받으면, 수업명 + 학생 이름으로 "내가 가지고 있음" 등록 (서면/대면 구분 없이 단순 소지 여부만)
- 학생 이름으로 검색하면 현재 누가 답안지를 가지고 있는지 바로 확인 가능
- 학생이 보강으로 다른 학원 반으로 이동한 경우, 관리쌤이 이동 사실을 알게 되는 시점에 직접 기록

**C. 사용자 인증**
- 이름 + 4자리 번호로 간단 로그인 (본인 확인용, 복잡한 계정 시스템 아님)
- 역할(첨삭진/관리쌤)에 따라 볼 수 있는 화면이 다름

### 선택 기능 (이번 범위 밖, 추후 논의)
- 정산/급여 계산 자동화
- 첨삭닷컴·네이버 카페 업로드 연동
- 출석부 사진 기반 기록 대체
- 채점표·논제 자료 관리 (첨삭방 관련 기능)

## 4. 기술 스택

*추후 결정 — Claude Code와 대화하며 정할 항목*

- 로그인/역할 구분 방식 (이름+번호 기반 간단 인증을 어떻게 구현할지)
- 데이터 저장 방식 (여러 사용자가 함께 보고 수정하는 데이터이므로, 개인 저장이 아닌 공유 저장 방식이 필요함)
- 실시간 반영 여부 (요청/승인 상태가 여러 사용자 화면에 즉시 반영되어야 하는지)

## 5. 화면 구성

1. **로그인 화면**: 이름 선택 + 4자리 번호 입력
2. **홈 화면**: 역할 구분 없이 전체 수업을 요일별 주간 캘린더로 표시 (첨삭진/관리쌤 모두 모든 학원·모든 첨삭진의 수업을 동일하게 봄)
3. **일정표 화면**: 날짜/학원/시간/반/배정 첨삭진/인원/상태를 표로 확인
   - 첨삭진 로그인: 본인 이름이 배정 첨삭진에 포함된 행만 표시
   - 관리쌤 로그인: 전체 행 표시 + 행을 클릭해 학생 수·배정 첨삭진 명단을 인라인으로 수정 가능 (첨삭진 계정에는 수정 기능이 보이지 않음)
4. **요청/승인 화면**:
   - 첨삭진용: 참석 요청/불참 요청 보내기
   - 관리쌤용: 승인 대기 요청 목록, 승인/거절 처리
5. **답안 소지 현황 화면**: 학생 이름 검색, 현재 소지자 확인, 배분받은 답안지 등록, 보강 이동 기록(관리쌤 전용)

## 6. 상세 기능 명세

- **참석/불참 요청 (첨삭진 → 관리쌤)**: 첨삭진이 특정 날짜·반을 선택해 "불참" 또는 "대타 필요" 요청 등록 → 관리쌤 승인 대기 목록에 표시 → 관리쌤이 승인하면 일정표에 반영
- **인원 모집 요청 (관리쌤 → 첨삭진)**: 관리쌤이 특정 반에 "인원 필요" 공지 등록 → 첨삭진들이 참석 가능 여부 응답 → 관리쌤이 확정 인원 선택 후 일정표에 반영
- **답안지 소지 등록**: 첨삭진이 배분받은 직후, 수업(날짜/반)과 학생 이름을 선택해 "소지 중" 상태로 등록
- **답안지 소지 검색**: 학생 이름으로 검색하면 현재 소지자(첨삭진 이름)와 등록 시각이 표시됨
- **보강 이동 기록**: 관리쌤이 학생 이름, 원래 반, 이동한 반을 입력하면 관련된 첨삭진들이 확인할 수 있도록 표시
- **일정표 학생 수/배정 첨삭진 수정 (관리쌤 전용)**: 관리쌤이 일정표 화면에서 행을 클릭하면 학생 수와 배정 첨삭진 명단을 인라인 폼으로 수정할 수 있음. 저장하면 일정표와 홈 화면 캘린더가 같은 데이터를 공유하므로 두 화면 모두 즉시 갱신됨 (프로토타입 메모리 상에서만 유지, 새로고침 시 초기값으로 복원)

### 왜 이런 방향인가

- 사용 시점이 대부분 **수업 사이 쉬는 시간, 수업 끝난 직후**처럼 바쁜 순간
- 여러 사람이 각자 다른 목적(참여 확인, 답안지 찾기, 승인 처리)으로 들어옴
- 정보량이 많음 (수업 수, 학생 수, 요청 건수) → 화면이 복잡해지기 쉬움
- 그래서 원칙은 하나: **"찾으려는 정보가 3초 안에 눈에 들어와야 한다"**

### 레이아웃 원칙

1. **목록/표 중심 구성**: 카드보다는 표(테이블) 형태가 정보 밀도가 높은 이 서비스에 더 적합
2. **검색창은 항상 상단 고정**: 학생 이름으로 답안지 소지자를 찾는 게 핵심 동작이므로, 스크롤해도 검색창이 항상 보이면 좋음
3. **역할별 뱃지 표시**: 이름 옆에 "첨삭진" / "관리쌤" 같은 작은 뱃지를 붙여, 누가 누구인지 헷갈리지 않게
4. **승인 대기 목록은 별도 영역으로 분리**: 관리쌤 화면에서 "지금 처리해야 할 것"이 다른 정보에 묻히지 않도록 상단 또는 별도 탭으로 구분

### 반응형 (모바일 우선)

- 첨삭진들은 대부분 **수업 중 휴대폰으로** 확인/입력할 가능성이 높음
